01 / INTRODUCCIÓN

¿Qué es MoviPass?

Una plataforma que conecta la administración del transporte con el proceso de compra de un pasaje.

El proyecto permite a las cooperativas administrar buses, frecuencias y hojas de ruta. Para los viajeros, contempla la búsqueda de viajes, selección de asientos, registro del pago y obtención de un boleto con código QR.

↗

Para las cooperativas

Organizar la oferta de transporte: vehículos, rutas, horarios, precios y operación de la venta de boletos.

⌁

Para los viajeros

Consultar opciones de viaje y recorrer el proceso de compra, desde la elección del asiento hasta la consulta del boleto.

El alcance se resume a partir del README y los documentos del repositorio. El estado de cada tarea se consulta en Issues y Pull requests.

04 / INSTALACIÓN LOCAL

Prepara tu entorno de trabajo.

Necesitas Git, VS Code con Live Server y acceso al proyecto de Supabase del equipo. Node.js se utiliza para las tareas de la Supabase CLI.

1

Clona el repositorio y selecciona develop

La rama predeterminada integra el trabajo del equipo.

TERMINAL 
git clone https://github.com/kmoyolema3929/MoviPass.git
cd MoviPass
git checkout develop
2

Configura la conexión del frontend

Duplica frontend/js/config.example.js y nombra la copia config.js en la misma carpeta. En macOS o Linux puedes usar:

TERMINAL 
cp frontend/js/config.example.js frontend/js/config.js

Completa SUPABASE_URL y SUPABASE_ANON_KEY con la configuración proporcionada por el equipo. Respeta el formato del archivo de ejemplo.

3

Abre la aplicación con Live Server

Abre la carpeta frontend/ en VS Code. Dentro de frontend/pages/, haz clic derecho sobre la página que quieras probar y selecciona Open with Live Server. Utiliza la dirección local que indique la extensión.

Configuración del equipo. Según las reglas del repositorio, config.js y .env permanecen fuera de Git. No incluyas claves de servicio, contraseñas ni tokens en la documentación pública.

Si vas a trabajar con migraciones

Esta tarea requiere acceso de la persona responsable de la base de datos. Copia .env.example como .env y sigue la guía de migraciones para vincular el proyecto y aplicar cambios.

CREAR UN ARCHIVO DE MIGRACIÓN 
npx supabase migration new nombre_descriptivo
05 / MODELO DE DATOS

Los datos detrás del viaje.

Consultar modelo completo ↗

El documento de diseño agrupa las entidades alrededor de usuarios, transporte, viajes y venta de boletos.

Entidades descritas en el modelo de datos
ÁreaEntidades del diseño
Usuarios y avisosperfiles y notificaciones.
Transportecooperativas, buses, tipos_bus y asientos.
Planificaciónfrecuencias, paradas y hojas_ruta.
Operación y ventaviajes, boletos, pasajeros y pagos.

Convenciones compartidas

  • Tablas en español, en plural y con nombres snake_case.
  • Clave primaria id de tipo uuid; claves foráneas con el formato bus_id o viaje_id.
  • Fechas como creado_en y salida_en, de tipo timestamptz.
  • Migraciones versionadas dentro de supabase/migrations/.
  • RLS activado en cada tabla nueva, con políticas de acceso definidas en su migración.

Estas entidades describen el modelo documentado. Para conocer el esquema implementado, revisa las migraciones del repositorio.

09 / PREGUNTAS FRECUENTES

Antes de comenzar.

¿Esta página permite comprar pasajes?

Es el portal de documentación del proyecto. La aplicación se referencia en el README en movipass.netlify.app y utiliza la configuración de Supabase del equipo.

¿Necesito XAMPP o un servidor PHP?

El stack documentado utiliza HTML, CSS, JavaScript, Bootstrap y Supabase. Para ejecutar la interfaz en local se indica Live Server; las tareas de base de datos utilizan la Supabase CLI.

¿Por qué no veo datos al ejecutar el frontend?

Comprueba que creaste frontend/js/config.js desde el ejemplo y que el equipo te proporcionó la configuración correcta. Revisa también tu sesión, los permisos del rol y los errores que muestre la consola del navegador.

¿Dónde reporto un error o solicito un cambio?

Utiliza los issues del repositorio y la plantilla correspondiente. Consulta SUPPORT.md y el proceso de control de cambios.

¿Dónde encuentro las condiciones de uso del código?

El repositorio declara la licencia GNU GPL v3. Consulta LICENSE para conocer el texto aplicable.
